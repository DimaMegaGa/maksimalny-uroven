# Подключение к MAX

Школьная платформа размещается на собственном HTTPS-хостинге. MAX открывает её
в WebView; Python-сервер, база, роли, проверка работ и обмен баллов продолжают
работать на этом хостинге. Отдельный непрерывный процесс бота не нужен:
события приходят в WSGI по webhook.

## Что реализовано

- `frontend/max-bridge.js` подключает официальный MAX Bridge при запуске с
  параметрами MAX. Стартовый hash сначала читает SDK, затем запускается школьный
  маршрутизатор. В обычном браузере SDK не загружается. При сбое CDN сайт
  запускается через пять секунд. Кнопка «Назад» закрывает диалог или возвращает
  на главную.
- `backend/max_bot.py` обрабатывает начало личного диалога и `/start`, `/help`, `/status`, `/about`, `/stop`.
  Бот показывает описание и кнопку платформы. Чужие webhook-запросы отсекаются
  по секрету; повторы учитываются в отдельной SQLite. Тексты чатов не сохраняются.
- Вход остаётся по выданному школой ФИО и коду. Непроверенные `initDataUnsafe`,
  имена и параметры MAX не дают доступа к аккаунтам. Автоматическое связывание
  MAX ID со школьными профилями здесь не реализовано. Уведомления подключаются
  отдельно через одноразовую ссылку. При действиях из мини-приложения сервер
  проверяет подписанные стартовые данные MAX и сверяет получателя.

## Конфигурация на сервере

Приватный `runtime/max-bot.json` (Linux: права `0600`):

```json
{
  "token": "BOT_TOKEN",
  "secret": "RANDOM_WEBHOOK_SECRET_AT_LEAST_32_CHARACTERS",
  "username": "your_bot",
  "site_url": "https://your-school.example/",
  "webapp_registered": false
}
```

Файл не публикуется через HTTP и не включается в исходный архив. Токен не
добавляется в JavaScript, GitHub, URL или журналы. `runtime/max-events.sqlite3`
хранит только хеши событий/диалогов и время для подавления повторов. Успешные
ответы учитываются сутки. Если сеть оборвалась уже после принятия сообщения
MAX, при повторе webhook теоретически возможен повтор ответа.

Если задан `MAKS_DB_PATH`, приватная конфигурация и журнал событий размещаются
в каталоге рядом с этой базой. В Docker это том `/data`, поэтому файл
конфигурации имеет путь `/data/max-bot.json` и переживает замену контейнера.

Сертификат `backend/russian_trusted_root_ca.pem` — публичный корневой сертификат
Минцифры, а не секретный ключ. Клиент сверяет SHA-256 с опубликованным MAX
отпечатком и добавляет доверие только для API-клиента приложения. Проверка TLS
и системное хранилище сертификатов не отключаются и не меняются.

## Активация

1. Перезапустить WSGI после установки файлов. Проверить, что POST
   `/api/max/webhook` с неверным секретом возвращает 403.
2. Проверить токен запросом GET `https://platform-api2.max.ru/me` с заголовком
   `Authorization: TOKEN`. Убедиться, что username относится к нужному боту.
3. Проверить GET `/subscriptions`. Не удалять подписки другого сервиса и не
   запускать параллельный Long Polling.
4. POST `/subscriptions` с телом:

```json
{
  "url": "https://your-school.example/api/max/webhook",
  "update_types": ["bot_started", "message_created"],
  "secret": "SAME_SECRET_AS_IN_PRIVATE_CONFIG"
}
```

5. В настройках существующего бота в MAX для бизнеса сохранить HTTPS-адрес
   школьного сайта в поле URL мини-приложения. Это действие нельзя заменить
   токеном Bot API. Кабинет министерства остаётся доступным по `/ministry/`.
6. Только после регистрации адреса и проверки запуска внутри MAX изменить
   `webapp_registered` на `true`. До этого бот использует честную обычную
   ссылку; после — кнопку `open_app`. Перезапуск для изменения этого флага
   не требуется.
7. Проверить с телефона: старт бота → приложение → вход ученика → работа →
   проверка учителем → баланс → запрос обмена → решение учителя; затем
   аватар, вложения, уведомления и кнопку «Назад».

## Проверки без действующего токена

```sh
python tests/test-max-bot.py
node tests/test-max-bridge.cjs
python backend/test_container.py
node tests/test-client.cjs
```

Первые две команды не вызывают настоящий MAX API и не отправляют сообщения.

## Меню бота

В личном чате доступны `/start`, `/help`, `/status`, `/about` и `/stop`.
Каждый ответ содержит кнопку открытия платформы, помощь, проверку подключения и описание проекта.
`/status` проверяет привязку по отправителю MAX и его личному чату: чужие школьные профили и коды не выдаются.
На обычный текст бот отвечает короткой подсказкой, не повторяя введённый текст. Частые запросы ограничены.
Ответы навигации приходят без звука, а школьные уведомления сохраняют обычный режим оповещения.

Для установки подсказок команд на собственной копии с настроенным приватным конфигом бота:

```sh
python scripts/configure_max_commands.py
```
