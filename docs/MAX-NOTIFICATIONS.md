# Уведомления платформы в MAX

Ученик или учитель открывает свой профиль → «Уведомления MAX» → «Подключить MAX».
Далее он открывает одноразовую ссылку на бота и подтверждает запуск. Если клиент
MAX не передал параметр ссылки, ту же одноразовую команду можно отправить боту
вручную. Это отдельное подключение доставки, оно не меняет регистрацию мини-приложения.

После подключения новые записи из личных уведомлений платформы автоматически
попадают в очередь MAX: опубликованные задания, отправленные работы, результаты
проверки, достижения и решения по обмену. Существовавшие до подключения события
не пересылаются. Предмет и название задания добавляются для событий, связанных
с конкретной работой. Кнопка сообщения открывает платформу; если в приватной
конфигурации указан `webapp_registered: true`, используется `open_app`.

Отключение: кнопка в профиле или `/stop` в личном чате бота. Одна школьная учётка
соответствует одному пользователю MAX. Для смены сначала отключают прежнюю
привязку. Неподключённым пользователям бот школьные уведомления не отправляет.

## Размещение

Миграция создаёт таблицы `max_links`, `max_pairings`, `max_outbox` и SQL-триггер.
Он добавляет сообщение в очередь в той же транзакции, что и уведомление
платформы. Сбой MAX не отменяет опубликованное задание или начисление баллов.
База и ключи перед обновлением сохраняются в закрытую резервную копию.

Раз в минуту штатный планировщик хостинга запускает короткую команду:

```sh
python scripts/deliver_max_notifications.py --database /absolute/path/to/runtime/maks.sqlite3
```

Укажите в планировщике Python 3.13 и абсолютный путь к скрипту. Процесс не
остаётся в фоне. При работе в Docker такую же команду запускает планировщик
с доступом к тому `/data`. Сам Docker Compose планировщик не добавляет.
При отсутствии планировщика сообщения остаются в очереди, пока команда не будет запущена.

За один запуск обрабатывается до 20 сообщений. Между отправками выдерживается
0,6 секунды. Параллельные обработчики используют аренду записи. После
подтверждённой отправки запись повторно не выбирается. Временные ошибки
повторяются с увеличением интервала, максимум шесть попыток. После исчерпания
попыток профиль показывает наличие недоставленных сообщений. Проверьте, что
бот не заблокирован; отключение и повторная привязка отменяют прежнюю очередь.

Если MAX принял сообщение, но соединение оборвалось до получения ответа,
повторная попытка может дать дубль: API не предоставляет ключ идемпотентности
для этой операции. При очень большой очереди доставка может занять больше минуты.
Настройки звука, push и видимости текста на экране блокировки задаёт пользователь
в MAX и системе телефона; сайт не может принудительно включить их.

## Доступ и данные

- Подключение начинается только из авторизованного школьного профиля и
  подтверждается событием бота, проверенным секретом webhook.
- Одноразовая ссылка содержит случайный токен, а не ФИО или код школьного входа.
  В БД сохраняется только его SHA-256. Срок действия — пять минут.
- MAX user ID и личный chat ID хранятся на сервере для доставки. Они не входят
  в публичный список участников. Старые сообщения отменяются при смене привязки.
- Не отправляйте ссылку подключения другому человеку. Она подтверждает согласие
  на получение личных школьных событий. `/stop` не удаляет школьную учётную запись.
- Приватные конфигурация, база и резервные копии не входят в исходный ZIP.

Проверки: `python backend/test_container.py`, `python tests/test-max-bot.py`,
`node tests/test-max-bridge.cjs`, `node tests/test-client.cjs`.
