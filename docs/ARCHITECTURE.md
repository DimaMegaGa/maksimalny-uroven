# Устройство проекта

Два HTTP-процесса используют одну SQLite и разные cookie сеансов.
Роли, школы и доступ к конкретным работам и пакетам проверяет сервер.

| Модуль | Назначение |
|---|---|
| backend/server.py | HTTP API, cookie, выдача разрешённых файлов |
| backend/repository.py | SQLite, миграции, задания, ответы, баллы, история |
| backend/access_control.py | Авторизация и роли |
| backend/ministry.py | Импорт, пакеты, доставка и перевыпуск кодов |
| backend/roster_files.py | CSV/XLSX и сопоставление столбцов |
| backend/package_vault.py | Шифрование пакетов |
| backend/operations.py | Повторяемые запросы, медиа и управление заданиями |
| frontend/app.js | Общий клиент API и школьные страницы |
| frontend/director.js, frontend/ministry.js | Кабинеты управления доступом |
| frontend/reliability.js | Черновики, связь, календарный экспорт |
| frontend/workspace.js | Следующее действие, фильтры, статистика, архив |

## Данные и операции

Баллы начисляются и списываются сервером в транзакции. Идентификатор операции
защищает повтор одного запроса от двойного выполнения. Архив заданий обратим;
работы, результаты и история сохраняются.

Коды хешируются. Выданные списки кодов находятся внутри зашифрованных пакетов.
На Windows применяется DPAPI текущего пользователя; контейнер использует
отдельный ключ Fernet. Для переноса требуется миграция, одной SQLite недостаточно.

Текстовые черновики разделены по участнику и хранятся на устройстве семь дней.
Фотографии нужно прикреплять заново после перезагрузки. Медиа работ выдаётся
с проверкой доступа, состояние содержит ссылки вместо повторной передачи base64.

## Границы реализации

CSV/XLSX и ICS обеспечивают файловый обмен списками, результатами и сроками.
Автоматической синхронизации с внешним календарём, электронным журналом,
государственными реестрами нет. MAX и публичное размещение настраиваются отдельно.
