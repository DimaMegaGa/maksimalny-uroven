# Временный показ по HTTPS

Этот режим запускает два отдельных сайта на 8885/8887 и два временных HTTPS-туннеля.
Основная база и сайты на 8765/8767 не затрагиваются. Создаётся новая база с вымышленной
школой, четырьмя ролями и примерами заданий. Не добавляйте реальные персональные данные.

По умолчанию используется Serveo через встроенный Windows OpenSSH. Он не требует
бизнес-аккаунта и может показывать предупреждение перед открытием сайта.
Документация: https://serveo.net/docs/
Для проверки HTTPS используется актуальный CA-набор certifi из requirements.txt:
`python -m pip install -r requirements.txt`. Допускается локальная установка одного certifi
в `tools/python-packages` через `python -m pip install --target tools/python-packages certifi==2026.10.19`.
Системное хранилище сертификатов не изменяется; проверка TLS не отключается.
Альтернативный запуск: `python showcase.py --provider cloudflare`.
Для Cloudflare нужны Python 3.11+ и официальный cloudflared для Windows AMD64:
https://github.com/cloudflare/cloudflared/releases
Сохраните исполняемый файл как `tools/cloudflared.exe`. Проверяйте SHA256 по метаданным
официального релиза. Бинарный файл не входит в Git и Docker-образ.

Запуск: `start-showcase.cmd` или `python showcase.py`.
Ссылки и статус находятся в `runtime/showcase/status.json`.
Личные коды вымышленных участников — только в `runtime/showcase/PRIVATE_ACCESS.md`.
Эти файлы, база и журналы исключены из Git и Docker.
Для остановки: `stop-showcase.cmd` или `python showcase.py --stop`.
Остановка не удаляет базу: повторный запуск сохраняет изменения и коды.

Туннелю нужны доступный DNS и исходящее соединение с Cloudflare на порту 7844.
Если системный DNS не разрешает SRV-записи, можно проверить отдельный резолвер только
для процесса (не отключая проверку TLS и не меняя DNS Windows):

```powershell
$env:TUNNEL_DNS_RESOLVER_ADDRS = '1.1.1.1:53'
python showcase.py
```

Получение адреса ещё не означает успешного HTTPS-соединения.
Статус `ready` выставляется только после успешной внешней проверки обоих сайтов.
При сетевой ошибке контроллер завершает свои серверы и туннели, сохраняя базу и доступы.
Для ручной проверки используйте
внешние `/api/health`, страницу входа и авторизацию на обоих сайтах.
Ошибка 530 означает, что туннель ещё не доступен; смотрите локальные журналы.
Компьютер и оба процесса должны оставаться включёнными. При новом запуске адреса
меняются. Это временная демонстрация без гарантии доступности, не постоянный хостинг.
Документация: https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/

Сервер разрешает внешний POST только с точным Host и HTTPS Origin, заданным
через MAKS_PUBLIC_ORIGIN. Для внешнего входа выдаются Secure/HttpOnly cookie.
Удалённая остановка запрещена. Звёздочки и произвольные сторонние Origin не разрешены.
Режим не подключает кнопку мини-приложения к MAX и не реализует авторизацию по MAX initData.

При проверке 30 октября 2026 Cloudflare не установил соединение в текущей сети.
Первоначальная проверка Serveo системным CA-набором Python сообщала об ошибке срока
сертификата в цепочке. С поддерживаемым certifi HTTPS-проверка успешно проходит;
Windows и браузер также принимают HTTPS без обхода сертификатных предупреждений.
Serveo проверен на обоих сайтах: HTML, health, вход/сеанс/выход четырёх ролей,
Secure/HttpOnly cookie, отклонение чужого Origin. Использовались только вымышленные участники.
Не отключайте проверку TLS и не обходите предупреждения браузера о сертификатах.

Проверенные альтернативы: localhost.run и ssh.localhost.run — тайм-аут SSH;
tunnl.gg — тайм-аут соединения; Pinggy — отказ анонимной авторизации;
Tunnelmole — сброс TLS-соединения с service.tunnelmole.com:8083.
Клиент LocalTunnel выделил адрес loca.lt, но полноценный вход через него не проверялся:
к этому моменту Serveo уже прошёл полную проверку. Клиенты альтернатив установлены
только в служебной рабочей папке и не являются зависимостями сайта.
