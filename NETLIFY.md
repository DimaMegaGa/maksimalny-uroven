# Размещение интерфейса на Netlify

Конфигурация готова для импорта этого репозитория. Полноценная публикация пока
требует отдельно размещённого Python API. Netlify не запускает наш постоянный
HTTP-процесс и локальную SQLite как Docker/VPS. Python в сборке используется для
подготовки файлов, а не для работы API после публикации.

## Настройки проекта

- Репозиторий: `DimaMegaGa/maksimalny-uroven`, ветка `main`.
- Сборка и каталог публикации заданы в `netlify.toml`.
- `MAKS_SITE`: `school` для школы или `ministry` для отдельного проекта министерства.
- `MAKS_API_ORIGIN`: HTTPS origin соответствующего Python API без пути, например
  `https://api.example.org`. Задать для сборки и для Functions.
- На сервере API `MAKS_PUBLIC_ORIGIN` должен совпадать с его собственным HTTPS origin.
  При внешнем размещении API требуется также корректная настройка прокси и Host.
- Токен бота MAX и базу в Netlify frontend загружать не нужно.

Для двух порталов создаются два проекта с разными `MAKS_SITE` и API origin.
Оба Python-сервера должны использовать одну постоянную базу и один ключ пакетов.

## Проверки и защита

Сборка обращается к `/api/health` и проверяет тип приложения и портал. Если адрес не
настроен, недоступен или относится к другому порталу, сборка останавливается.
В публикацию копируются только HTML, CSS, JS, иконки и статический site-config.js.
Каталоги backend, runtime, SQLite, секретные коды и ключи не публикуются.

Функция `netlify/functions/api.mjs` принимает запросы `/api/*` и передаёт их в
Python API. Она проверяет Origin и служебный заголовок POST, переносит cookie
без добавления Domain, запрещает удалённую остановку и переходы на сторонний адрес,
возвращает JSON при сетевой ошибке. Лимит тела шлюза — 5,5 МБ; большие фотографии
нужно уменьшить. Авторизация и расчёт баллов остаются в Python.

Шлюз проверяет исходный Origin Netlify и только после этого устанавливает Origin
сервера API для внутреннего запроса. Сам токен сеанса дополнительно проверяет Python.

Проверки локально: `node tests/test-netlify.mjs` и `python scripts/test_netlify_build.py`.
GitHub Actions также проверяет шлюз.

## Текущий статус

Оба интерфейса и API-шлюзы опубликованы через официальный Netlify CLI:

- Школа: https://maksimalny-uroven-30.netlify.app
- Министерство: https://maksimalny-uroven-ministry-30.netlify.app

GitHub-аккаунт подключён, но автоматическая публикация из репозитория пока не
настроена: текущая публикация выполнена вручную через CLI. Новые коммиты сами по
себе её не обновляют. Оба production-сайта открыты публично с подтверждения
владельца. Внутренняя авторизация платформы сохранена.

В текущей демонстрации API использует отдельную базу с вымышленными участниками
на локальном компьютере. База, ключи и персональные коды не загружены в Netlify.

Serveo можно использовать только для короткой проверки. Даже при постоянном
адресе Netlify истечение туннеля отключит API. Для постоянной работы нужен
постоянный API-хостинг с сохранением базы и ключа.
