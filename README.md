# МАКСимальный уровень

Школьная платформа и отдельный портал управления доступом. Сценарий показа: [SHOWCASE.md](SHOWCASE.md).
Временный бесплатный показ по HTTPS на отдельной базе: [SHOWCASE-HTTPS.md](SHOWCASE-HTTPS.md).
Подготовка интерфейса для Netlify и требования к API: [NETLIFY.md](NETLIFY.md).

Запуск обоих сайтов: `start.cmd`. Школьная платформа: http://127.0.0.1:8765.
Отдельный портал министерства: http://127.0.0.1:8767 (`start-ministry.cmd`).
Остановка обоих сайтов: `stop.cmd`. Резервная копия: `backup.cmd`.
Нужен Python 3.11+. Обычный Windows-запуск использует встроенный DPAPI без дополнительных библиотек.
Для переносимого шифрования и Docker установите зависимости из `requirements.txt`.
Ручной запуск школы: `python backend/server.py --site school --port 8765`.
Ручной запуск министерства: `python backend/server.py --site ministry --port 8767`.
Для запуска без открытия окон браузера: `python start.py --no-browser`.

Это два отдельных локальных сайта с общей SQLite и разными cookie сеансов. В одном браузере
можно одновременно работать министерством на 8767 и директором на 8765.
На школьной странице доступны только ученик, учитель и директор; вход министерства вынесен на 8767.
Ранее выданные коды и пакеты сохраняются.
Не открывайте HTML через file:// или Live Server: нужен API Python-сервера.

## Доступ

Свободная регистрация отключена. Министерство загружает CSV с ФИО, ролями и классами,
сервер генерирует персональные коды и формирует пакет с инструкцией.
После отправки пакет появляется в кабинете назначенного директора, аккаунты активируются.
Директор распределяет коды; ученик и учитель входят по ФИО и коду.

Для первого входа локально запустите `create-director.cmd` (назначьте школу), затем `create-ministry.cmd`.
Коды руководителя и министерства показываются в локальном окне, сохраняйте их лично.
Подключения к настоящему Министерству образования нет.
Вход министерства доступен только на отдельном портале 8767.
Полная инструкция, ограничения, восстановление доступа: [ACCESS.md](ACCESS.md).
Шаблон таблицы: `templates/roster-template.csv`; в интерфейсе есть кнопка скачивания.
Старые тестовые данные сохранены. Профили без нового доступа можно подхватить импортом по совпадающим данным.

## Возможности

Задания ученику, классу и параллели; ответы и фото; проверка учителем, комментарии,
доработка и отказ; баллы, уровни, достижения, рейтинг, обмен и история.
Кабинет министерства: импорт и проверка таблиц, черновики, защищённые списки с кодами,
доставка директорам и перевыпуск. Кабинет директора: входящие, инструкции, списки участников,
скачивание CSV, отметки прочтения и распределения.

Адаптив: до 767 px — нижняя навигация, 768–1199 px — компактная панель,
от 1200 px — полная боковая панель. Профиль открывается верхним аватаром.

## Данные и проверка

SQLite: `backend/data/maks.sqlite3`, вне каталога сайта. Переопределение: `MAKS_DB_PATH`.
Схема обновляется автоматически. Хеши кодов и токенов хранятся отдельно от зашифрованных пакетов.
На основных портах 8765/8767 сохранены прежние имена cookie. Копии на других портах
используют отдельные cookie, поэтому их вход не заменяет сеанс основной установки.
Для пакетов используется Windows DPAPI текущего пользователя; перенос базы на другой ПК/в облако
требует миграции шифрования и резервирования ключей. Подробности в ACCESS.md.
Не публикуйте data/, backups/, logs/, реальные списки и коды в GitHub.
`backup.cmd` делает согласованную SQLite-копию; пакеты в ней остаются зашифрованными.
Для восстановления остановите сервер и отдельно сохраните текущую базу перед заменой резервной копией.

Тесты: `python backend/test_local.py`, под обычной учётной записью Windows.
Используется отдельная временная база: проверяются роли, импорт, границы доступа к пакетам,
активация при отправке, перевыпуск, сохранение прежних данных, задания, баллы и обмен.
Текущий контракт выдачи описан в ACCESS.md; `API-original.md` — историческая заготовка.
Регрессионные проверки интерфейса (нужен Node.js 18+): `node tests/test-client.cjs`.
Отчёт о проверке локальной и внешней версий: [BUGFIX_REPORT.md](BUGFIX_REPORT.md).

## MAX и размещение

Авторизация MAX, ведомственные реестры, внешние push и публикация GitHub пока не подключены.
Локальный адрес доступен только на этом ПК. Для мини-приложения нужны публичный HTTPS,
рабочий сервер, проверка данных MAX и привязка подтверждённой личности к школьному профилю.
Локальная HTTP-оболочка не предназначена для внешнего размещения.

## Запуск в Docker

Нужен Docker Engine или Docker Desktop с Linux-контейнерами и Docker Compose v2.
Выполняйте команды из корня репозитория. Остановите местные серверы на 8765/8767,
если они уже работают: контейнеры используют те же порты.

```sh
docker compose build
docker compose up -d
docker compose ps
```

Школа: http://127.0.0.1:8765. Портал министерства: http://127.0.0.1:8767.
Оба контейнера используют общую новую SQLite в томе `maks-data`.
База с вашего компьютера автоматически не копируется. Реальные данные не входят в образ.
Первоначальные административные аккаунты создаются командами:

```sh
docker compose exec school python backend/manage_access.py create-director --school "Школа №1" --label "Директор"
docker compose exec ministry python backend/manage_ministry.py create --label "Оператор министерства"
```

Каждая команда однократно показывает персональный код. Сохраните его приватно.
Войдите министерством, выберите созданную школу и загрузите `templates/roster-template.csv`.
Создайте пакет и отправьте директору. Затем войдите директором на школьном сайте,
откройте пакет и получите коды учеников/учителей.

```sh
docker compose logs --tail 50
docker compose stop
docker compose start
docker compose down
```

`down` сохраняет том. `down -v` удаляет базу и ключ: не используйте его для обычной остановки.
В `/data/vault.key` автоматически создаётся секретный ключ Fernet; оба сайта используют его.
Резервируйте согласованную копию SQLite и ключ отдельно в защищённом месте.
Без исходного ключа расшифровать пакеты нельзя. Старые Windows DPAPI-пакеты
этот режим автоматически не переносит: для переноса нужна отдельная миграция под исходным Windows-пользователем.
Не подключайте существующую Windows-базу к контейнеру без такой миграции.

Сборка и запуск одного контейнера без Compose (школьный сайт):

```sh
docker build -t maks-level:local .
docker volume create maks-single-data
docker run -d --name maks-school -p 127.0.0.1:8765:8765 -v maks-single-data:/data maks-level:local
docker exec maks-school python backend/manage_access.py create-director --school "Школа №1"
docker stop maks-school
```

Контейнеры намеренно доступны только с этого компьютера. HTTPS-хостинг и интеграция
с MAX выполняются отдельно; эти команды не публикуют проект в интернете.
По умолчанию сервер принимает только локальные Host/Origin. Временный HTTPS-режим
разрешает дополнительно один точный адрес через MAKS_PUBLIC_ORIGIN; это не настройка постоянного хостинга.

## Запуск из командной строки без Docker

В Windows можно пользоваться `start.cmd` или командами выше. Для нового переносимого
запуска на Windows/Linux/macOS сначала создайте виртуальное окружение:

```sh
python -m venv .venv
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
$env:MAKS_DB_PATH = "$PWD/runtime/maks.sqlite3"
$env:MAKS_VAULT_KEY_FILE = "$PWD/runtime/vault.key"
python backend/container_start.py --site school --port 8765
```

Linux/macOS:

```sh
. .venv/bin/activate
python -m pip install -r requirements.txt
export MAKS_DB_PATH="$PWD/runtime/maks.sqlite3"
export MAKS_VAULT_KEY_FILE="$PWD/runtime/vault.key"
python backend/container_start.py --site school --port 8765
```

В другом терминале активируйте то же окружение и задайте те же переменные,
затем запустите `python backend/container_start.py --site ministry --port 8767`.
Первый сервер должен запуститься до второго. Для создания администратора используйте
те же команды `manage_access.py` / `manage_ministry.py` без префикса `docker compose exec ...`.
Вне Docker сервер по умолчанию слушает только `127.0.0.1`.

## Материалы второго тура

Бот команды: https://max.ru/ideya_fiks_30_bot. Наличие ссылки не означает,
что запуск мини-приложения уже настроен.
В репозиторий входят исходники, Dockerfile, compose.yaml, requirements.txt и этот README.
Dockerfile — рецепт сборки; собранный образ является отдельным артефактом.
Чтобы подготовить архив образа для GitHub Release:

```sh
docker build -t maks-level:submission .
docker save -o maks-level-image.tar maks-level:submission
```

Приложите архив к Release и укажите ссылку на него в описании сдачи.
Эксперт может загрузить образ командой `docker load -i maks-level-image.tar`.
GitHub Actions в `.github/workflows/container.yml` также собирает образ, запускает тесты
и прикладывает архив к результату запуска. Публикация репозитория/Release ещё не выполнена.
Фактическая Docker-сборка на текущем ПК пока не проверена: Docker не установлен.
Не публикуйте токен бота, SQLite, ключи, реальные ФИО, коды или локальные журналы.
