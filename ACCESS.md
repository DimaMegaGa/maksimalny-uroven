# Доступ через списки министерства

Это демонстрационный кабинет внутри нашей платформы. Связи с настоящим Министерством образования, MAX, электронной почтой или государственными реестрами нет.

## Первоначальная настройка

1. Запустите `start.cmd`: школа работает на http://127.0.0.1:8765, министерство — на http://127.0.0.1:8767.
   Только министерство можно запустить файлом `start-ministry.cmd`.
2. Запустите `create-director.cmd`, укажите точное название школы, сохраните показанный код директора.
3. Запустите `create-ministry.cmd` и сохраните код демонстрационного кабинета министерства.
4. Войдите по коду министерства на отдельном сайте http://127.0.0.1:8767. Директор входит на школьном сайте http://127.0.0.1:8765.
   Существующие коды продолжают действовать; новая регистрация не требуется.

Оба кода показываются только в локальном окне создания. Не отправляйте их в общий чат.
Чтобы подхватить прежние тестовые профили, используйте точное существующее название школы, например «Тестовая Школа».
У министерства и школьного сайта разные cookie сеансов. Можно войти министерством и директором одновременно в двух вкладках одного браузера.
Выход на одном сайте не завершает сеанс на другом. API каждого сайта проверяет роль, а не только видимость вкладок.
Создавать министерство и директоров через публичную форму сайта нельзя: это делает локальный администратор.

## Таблица

В кабинете министерства нажмите «Загрузить список» → «Скачать шаблон CSV».
Копия шаблона: `templates/roster-template.csv`.

| ФИО | Роль | Класс |
|---|---|---|
| Иванов Иван Иванович | ученик | 8А |
| Петрова Анна Сергеевна | учитель | |

Школа и директор выбираются в форме, поэтому их не нужно повторять в строках.
Укажите ровно три заголовка: `ФИО;Роль;Класс`. Роли: ученик/учитель либо student/teacher.
Класс ученика: 1–11, при необходимости с одной буквой. Для учителя класс пустой.
ФИО до 80 символов. До 200 участников и 300 КБ на один файл.
В Excel выберите «Сохранить как» → CSV UTF-8. Поддерживается также Windows-1251, разделитель точка с запятой, запятая или табуляция.
Прямой импорт XLS/XLSX сейчас не реализован; сохраните таблицу в CSV.

## Формирование и доставка

1. Выберите организацию и назначенного ей директора. Если получателей нет, создайте директора локальной командой.
2. Загрузите CSV, задайте название и при необходимости сопроводительное сообщение.
3. Нажмите «Проверить таблицу». Ошибки показываются по строкам. Никакие аккаунты на этом шаге не создаются.
4. Исправьте ошибки и нажмите «Создать аккаунты и пакет с кодами».
5. Сервер создаст случайные индивидуальные коды и аккаунты в одной транзакции. При ошибке не сохраняется часть списка.
6. Пакет появится в «Отправлениях» как черновик. Он уже содержит коды, но новые аккаунты ещё неактивны.
7. Проверьте список и инструкцию, нажмите «Отправить директору».
8. Сервер активирует аккаунты и доставит пакет во «Входящие» конкретного директора. В его кабинете появится счётчик новых сообщений.

Уведомление находится внутри платформы: при открытом кабинете обновляется обычным опросом сервера, после следующего входа также видно.
Почтовые сообщения, мобильные push и уведомления MAX не отправляются.
Пакет доступен отправителю и указанному директору. Другой директор, даже из той же школы, не получает содержимое автоматически.
Операторы министерства имеют общий реестр школ и аккаунтов этой демонстрационной установки; разграничение по регионам пока отсутствует.

## Выдача директором

Директор открывает «Входящие», затем «Открыть список и инструкцию».
Доступны таблица с ФИО и кодами, скачивание CSV и текстовой инструкции.
Сообщение отправителя дополняется стандартным порядком выдачи.
Передавайте участнику только его строку, не общий список с чужими кодами.
Участник выбирает роль ученика или учителя и вводит ФИО и персональный код; школа и класс берутся из базы.
После выдачи директор отмечает пакет как распределённый. Это ручная отметка директора, а не доказательство входа каждого участника.
Министерство видит факт первого открытия и распределения.
У директора больше нет создания аккаунтов и генерации кодов; прежние серверные маршруты выдачи также закрыты.

## Повторы и старые профили

Повтор уже созданного аккаунта в той же школе, с теми же ФИО, ролью и классом блокируется.
Повторные строки внутри файла блокируются. Если есть ошибки, весь импорт не выполняется.
Старый профиль без нового механизма доступа подхватывается по школе, ФИО, роли и классу: сохраняются его ID, работы, задания, баллы и достижения.
Несколько старых профилей с одинаковыми данными требуют ручной сверки, автоматического объединения нет.
Два новых участника с полностью одинаковыми ФИО, ролью и классом также требуют ручной обработки: в этой версии нет отдельного внешнего идентификатора ученика.
Это нужно добавить при интеграции с настоящим ведомственным реестром.

## Потерянный код

Министерство открывает «Аккаунты» → «Перевыпустить код», выбирает директора-получателя.
Будет создан черновик отдельного пакета замены. Старый код ещё действует.
При отправке пакета старый код и все сеансы участника отзываются, новый начинает действовать.
Старые пакеты помечают заменённый код как неактуальный. Уже скачанные файлы автоматически удалить невозможно.
При конфликте двух черновиков замены второй устаревший пакет не отправляется; нужно сформировать новый.

Код самого директора можно заменить локально:

```text
python backend/manage_access.py list-directors
python backend/manage_access.py reset-director --id ИДЕНТИФИКАТОР --interactive
```

Код министерства:

```text
python backend/manage_ministry.py list
python backend/manage_ministry.py reset --id ИДЕНТИФИКАТОР --interactive
```

## Хранение

Для проверки входа сохраняются PBKDF2-SHA256-хеши с солью (600000 итераций), токены сеансов тоже хешированы.
Секрет кода — 144 случайных бита; коды формирует сервер Python через secrets.
Для повторного скачивания директором нужна восстанавливаемая копия: содержимое пакетов хранится зашифрованным Windows DPAPI под учётной записью запуска сервера.
В обычном /api/state, общих списках и уведомлениях кодов нет. Содержимое выдаётся отдельным запросом после проверки прав; ответ имеет Cache-Control: no-store.
Закрытие диалога удаляет коды из его DOM. В localStorage/sessionStorage приложение их не записывает.
Скачанный CSV содержит открытые коды: храните его отдельно от общедоступных документов.
Администратор компьютера с доступом к учётной записи сервера может расшифровать пакеты; это не защита от владельца сервера.

Резервная копия базы включает зашифрованные пакеты, но не ключи профиля Windows.
На другом компьютере/под другой учётной записью Windows одного SQLite-файла недостаточно для открытия старых пакетов.
Перед переносом в облако нужен отдельный механизм шифрования (например, управляемый ключ сервера/KMS), миграция пакетов и проверенное резервное восстановление ключей.
Нельзя просто переносить эту DPAPI-схему на Linux: она явно откажет в работе вместо сохранения кодов открытым текстом.
Для новой контейнерной установки предусмотрен переносимый режим Fernet из библиотеки cryptography:
он включается переменной MAKS_VAULT_KEY_FILE, указывающей на файл секретного ключа.
Docker создаёт этот ключ в отдельном постоянном томе вместе с новой базой; ключ не входит в образ.
Старые DPAPI-пакеты автоматически не мигрируют. Подробные команды и правила резервирования — в README.md.
Сервер следует запускать обычным start.cmd под своей Windows-учётной записью, а не под изолированным техническим профилем.

## API

POST /api/ministry/preview — проверка CSV без записи.
POST /api/ministry/import — создание черновика и аккаунтов.
POST /api/ministry/reissue — черновик замены кода.
POST /api/packages/open — защищённое получение содержимого и отметка чтения директором.
POST /api/packages/send — доставка и активация (только отправитель).
POST /api/packages/distribute — отметка распределения (только получатель).
Все запросы используют JSON, сессию и заголовок X-Maks-Request: 1.
События создания, отправки, открытия и распределения записываются в delivery_audit без кодов.

## Отдельные сайты

Министерство и школа используют одну базу, поэтому пакет, отправленный с 8767, появляется у директора на 8765.
На 8767 разрешены вход министерства, просмотр его состояния, импорт, перевыпуск, открытие и отправка пакетов.
На 8765 разрешены школьные роли, задания и директорские входящие. Ведомственные операции на этом сайте закрыты.
Данные и коды не копируются между двумя базами: база остаётся общей.
Запуск создаёт отдельные журналы и управляющие файлы процессов, stop.cmd останавливает оба сервера.
Для размещения в интернете потребуются отдельные адреса, HTTPS и рабочая серверная конфигурация; эти адреса предназначены для локальных тестов.
